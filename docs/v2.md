## 通用图片和文件上传

**POST** `/common/upload`

需要登录，使用 `multipart/form-data` 上传单个 `file` 字段，不需要指定聊天对象。文件保存到 `config.yaml` 的 `file.upload_dir` 所配置目录，本地路径和元数据保存到 `files` 表。

图片支持 JPG/JPEG、PNG、GIF、WebP（最大 10 MiB）；任意其他文件类型最大 50 MiB。服务端会清理上传文件名并使用 UUID 作为磁盘存储名。`files` 表按上传者和 SHA-256 去重，同一上传者再次上传相同内容会复用已有文件记录。成功响应包含 `file_id`、`message_type`、`file_name`、`content_type`、`size` 和 `url`；聊天客户端用返回的 `file_id` 通过 WebSocket 发送 `message_type` 为 `2`（图片）或 `4`（文件）的消息。

## 下载图片或文件

**GET** `/files/{file_id}`

需要登录并携带 Bearer Token。上传者和收到该文件聊天消息的接收者可以下载；前端请求需附加 `Authorization` 头。图片以 `inline` 返回，普通文件以 `attachment` 返回。

成功响应是文件字节流，而不是 JSON。响应头包括 `Content-Type`、`Content-Disposition` 和 `X-Content-Type-Options: nosniff`。无效文件 ID 或本地文件已丢失时返回 `404`；无权访问返回 `403`。

## 清除会话未读数

**POST** `/conversation/read`

用户进入单聊或群聊会话时调用，清除当前用户该会话的未读数量。请求体：

```json
{
  "target_id": 456,
  "target_type": 1
}
```

`target_type` 为 `1` 单聊、`2` 群聊；`target_id` 为好友用户 ID 或群 ID。此操作只清除会话未读计数，不提供已读回执。当前群聊消息能力尚未实现。

成功响应：

```json
{
  "code": 200,
  "message": "ok",
  "success": true
}
```

重复调用是幂等的；如果当前用户没有对应会话行，也不会修改其他用户数据。
参数校验失败返回业务码 `400`，数据库错误返回 `500`。

## 注册与在线状态

### 注册

**POST** `/user/register`

下列字段均必填：`username`、`password`、`nickname`、`gender`、`birthday`。用户名遵循现有 4–16 位字母/数字/下划线规则；密码遵循现有 6–20 位规则；`gender` 为 `1` 男、`2` 女；`birthday` 格式为 `YYYY-MM-DD`，不能晚于今天。

请求示例：

```json
{
  "username": "alice_01",
  "password": "Abc123!",
  "nickname": "Alice",
  "gender": 2,
  "birthday": "2000-01-15"
}
```

成功响应为 `code: 200`、`message: "注册成功"`、`success: true`，不返回 Token；注册后再调用登录接口。用户名重复返回业务码 `1006`，参数或生日无效返回 `400`。

登录响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "jwt-token",
    "user_info": {
      "id": 123,
      "username": "alice_01",
      "nickname": "Alice",
      "gender": 2,
      "birthday": "2000-01-15",
      "presence_mode": "online",
      "avatar": "",
      "bio": "",
      "created_at": "2026-11-22T18:00:00+08:00"
    }
  },
  "success": true
}
```

`gender`、`birthday` 对迁移前的旧账号可能为空或省略。`presence_mode` 是用户设置的偏好，不是当前连接状态。

### 设置自己的在线偏好

**PUT** `/user/presence`

请求体：

```json
{
  "mode": "invisible"
}
```

`mode` 可为 `online` 或 `invisible`。实际在线还要求用户存在有效 WebSocket 连接；隐身用户仍可正常收发消息，但好友看到其为离线。成功响应的 `data` 包含当前 `mode` 和 `is_online`。

```json
{
  "code": 200,
  "message": "设置成功",
  "data": {
    "mode": "invisible",
    "is_online": false
  },
  "success": true
}
```

无效的 `mode` 返回业务码 `400`，其他设置失败返回 `500`。

### 获取和接收好友在线状态

`GET /friend/list?page=1&page_size=20` 的 `page`、`page_size` 均可选，默认分别为 `1`、`20`，最大每页 `100`。每个好友项包含 `is_online`；该字段在 `data.list[]` 项的顶层，而不在 `user` 对象中。

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "total": 1,
    "page": 1,
    "page_size": 20,
    "list": [
      {
        "friendship_id": 88,
        "remark": "",
        "group_id": 0,
        "created_at": "2026-11-22T18:00:00+08:00",
        "is_online": true,
        "user": {
          "id": 456,
          "username": "alice_01",
          "nickname": "Alice",
          "avatar": "",
          "bio": ""
        }
      }
    ]
  },
  "success": true
}
```

用户的 WebSocket 连接上线/断开或在线偏好发生可见变化时，已连接的好友端会收到：

```json
{
  "type": "presence.changed",
  "data": {
    "user_id": 456,
    "is_online": true
  }
}
```
